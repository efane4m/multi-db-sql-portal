# Отчёт об изменениях: backend-часть Multi-DB SQL Portal

Дата: 23 октября 2026 года.

## Область выполненной работы

Реализована backend-часть безопасного выполнения SQL, получения схемы БД,
предпросмотра таблиц, подсказок значений и проверки производительности.
Существующие авторизация, доменные модели и frontend сохранены; клиентский
адаптер изменён для совместимости с новыми API.

Документы для передачи команде:

- [Техническая документация и контракт API](BACKEND.md).
- [Результаты проверок](BACKEND-VALIDATION.md).

## Сравнение до и после

«До» описывает первоначально изученный код; старый backend отдельно не запускался.
«После» подтверждено просмотром кода, автоматическими тестами и тестовым запуском.

| Область | До | После | Что добавлено |
|---|---|---|---|
| Структура | SQL обрабатывался внутри `core/views.py` | Сервисы вынесены в `server/queries` | Отдельные модули доступа, схемы, парсера, выполнения, preview и кеша |
| SQL-безопасность | Проверка начала строки на SELECT | Разбор PostgreSQL AST и разрешённого подмножества SQL | Запрет нескольких команд, DML/DDL, INTO, блокировок, опасных функций и CTE |
| PostgreSQL-права | Общая учётная запись приложения | SQL API использует отдельную роль чтения | Read-only роль/транзакция, проверка привилегий, provisioning-команда |
| Доступ к БД | Фиксированные названия предметных БД | Проверяется реестр разрешённых БД и DatabaseAccess | Запрет default/internal aliases, проверка доступа до кеша |
| Схема | Клиент обращался к information_schema через общий SQL endpoint | Есть metadata API | Таблицы, колонки, типы, nullable, PK и FK |
| Предпросмотр | Отдельного API не было | API доступен с пагинацией и сортировкой | Ограниченный preview и точное число записей |
| Подсказки значений | SQL формировался на клиенте | Отдельный параметризованный API | Проверка поля, обработка префикса, до 10 вариантов |
| Выполнение JOIN | Ручной JOIN был возможен | JOIN проверен на связанных таблицах и большом объёме | Метаданные связей, интеграционные и нагрузочные сценарии |
| Результат | fetchall без общего серверного лимита | Серверный курсор и пакетное чтение | Лимиты строк/байтов, флаг truncated, сохранение типов |
| Таймауты | Не были заданы | Ограничены выполнение и ожидание блокировок | HTTP 408 и восстановление после отмены |
| Кеш | Общий ключ; пустые выборки не определялись как hit | Пользовательские ключи, кеш пустых результатов | SHA-256, нормализация SQL, refresh, обработка отказа Redis |
| Аудит | Отдельного журнала выполнения не было | Есть технический журнал без текста SQL и значений | Request ID, user ID, БД, длительность, строки и cache hit |
| Дополнительная БД | Требовала изменения фиксированных списков | Регистрируется через настройки | QUERY_DATABASES_JSON и динамический список выдачи доступа |
| Тестирование | Backend-тесты были пустыми | Проверяются API, PostgreSQL, безопасность и кеш | 28 успешно выполненных backend-тестов; отдельный opt-in Redis-тест |
| Производительность | Генератора и бенчмарков не было | Есть синтетические данные и измерения | Миллион строк, индексы, конкурентные запросы, планы и измерение Python-памяти |
| Интеграция frontend | Схема/подсказки шли через SQL API | Клиент использует metadata/suggestions API | API-адаптер и явный refresh для кнопки «Обновить» |

## Проверка результата

Повторно проверено на Windows, Python 3.12.14, Django 6.1.2 и PostgreSQL 18.4.
Использовались отдельные test_* и validation_* БД, без изменения рабочих БД.

| Проверка | Фактический результат |
|---|---|
| Django check и проверка миграций | Ошибок нет, незаписанных миграций нет |
| Полный backend-набор | 28 успешных тестов; 1 тест настоящего Redis пропущен |
| Frontend | 190 успешных тестов; production-сборка проходит |
| HTTP-сценарий | JWT, схема, preview, подсказки, JOIN, кеш и запреты SQL работают |
| Браузер | Вход/выход, профиль, реальная схема, выполнение из конструктора, ручной JOIN и cache hit работают |
| Опасный запрос в браузере | Несколько SQL-команд отклоняются с понятной ошибкой |
| Дополнительная БД | Проверены схема, preview, подсказки, COUNT, JOIN и кеш |
| Реальный Redis | Здесь не запускался; отказ кеша смоделирован тестами |
| Docker | Здесь не запускался: Docker CLI недоступен |

Последний повторный замер: миллион строк, три пробы, до двух запросов одновременно.
Измерялся Django/DRF API без сети и браузера; кеш — LocMemCache.

| Сценарий | Медиана без кеша, мс | Максимум, мс |
|---|---:|---:|
| COUNT по миллиону строк | 202.14 | 285.49 |
| Индексный фильтр | 82.93 | 191.14 |
| JOIN трёх таблиц с агрегированием | 430.76 | 547.80 |
| Большой результат с ограничением до 10 000 строк | 181.83 | 227.98 |

Предпросмотр — 99.12 мс; подсказки — 2.98 мс на таблице из 1 000 записей.
Эти измерения не гарантируют аналогичное время произвольного SQL и не доказывают
отзывчивость браузера при отображении 100 000 строк.

## Границы выполненной части

- API предпросмотра готов; отдельный экран предпросмотра ещё нужен.
- Метаданные для JOIN готовы; автодополнение `j → JOIN` в редакторе не добавлено.
- Шаблоны по-прежнему хранятся в localStorage; серверные шаблоны, история и настройки не добавлялись.
- CSV/JSON/XLSX существовали ранее; XML-экспорт не реализован.
- Виртуализация frontend и очередь с прогрессом выполнения не реализованы.
- Полная русификация Django admin остаётся отдельной задачей.
- Серверная и локальная демо-авторизация остаются разными режимами.
- Ручной SQL пока не показывает пользователю серверный флаг усечения результата.
- Задержка frontend перед запросом подсказок остаётся 250 мс; время API нельзя приравнивать к полной задержке интерфейса.
- Конфигурация остаётся development; перед production нужны отдельные настройки безопасности.

## Как проверить самостоятельно

Команды ниже выполняются в CMD из корня проекта при наличии Docker Desktop:

```bat
docker compose up -d --build
docker compose exec server python manage.py check
docker compose exec server python manage.py makemigrations --check --dry-run
docker compose exec server python manage.py test queries.tests --settings=server.integration_settings --noinput
docker compose exec -e PORTAL_TEST_REDIS_URL=redis://redis:6379/15 server python manage.py test queries.tests.test_redis --settings=server.test_settings
```

Для проверки запущенного API нужен серверный пользователь с доступом к db_stores:

```bat
powershell -NoProfile -File scripts\check-backend.ps1 -Database db_stores
```

Проверка большого объёма (замените YOUR_SERVER_USERNAME на свой серверный логин):

```bat
docker compose exec server python manage.py seed_benchmark --rows 1000000
docker compose exec server python manage.py configure_query_reader
docker compose exec server python manage.py benchmark_queries --username YOUR_SERVER_USERNAME --repeats 5 --workers 2 --explain
```

Интеграционные тесты создают/удаляют test_* базы; запускайте их на dev/test
окружении. Генератор добавляет отдельные bench_* таблицы без очистки предметных
данных. Подробности и дополнительные сценарии — в [BACKEND.md](BACKEND.md).
